# PBT on v3: nibble-row binary trie beside v3-hex

## Overview

- A new EIP-8297 binary-trie (PBT) commitment engine on the commitment-v3 architecture, replacing
  `PBinPatriciaHashed`. v3 stays the hex (MPT) engine.
- A record ("row") holds up to 16 cells covering one 4-bit window (4 binary levels) instead of 2 cells
  per binary node. Internal hashes inside a row are recomputed by the fold, never stored.
- Hex+bin dual mode (the EIP-8347 migration path: shadow bin arm per block, shadow roots, activation at
  `binaryTrieTime`, manual hex freeze) keeps working, with v3-hex as the hex arm.
- Roots stay bit-identical to the EIP-8297 reference (`merkelize(binarize(entries, 0))`) and to the
  current engine on every existing PBT suite.
- The fold reads commitment records and nothing else: no state read for an untouched leaf, no child-row
  read on a split, collapse or neighbour change.
- Folds run in parallel as in v3: storage buckets first, then header stems, code and the upper rows
  (binary-trie's engine folds sequentially).
- Out of scope, follow-up plans: bin witnesses (`debug_executionWitness` on the bin domain returns
  `ErrBinCommitmentUnsupported` from Task 10 on; `eth_getProof` and `eth_getWitness` already refuse bin
  blocks) and a bin prefetcher (only if Task 15 shows a need).

## Technical Details

### Row

- Window `w` covers bits `[4w, 4w+4)`; rows align to absolute nibble boundaries.
- A row exists iff its window holds a split, i.e. ≥2 cells (root forms below excepted).
- Each cell sits at its true slot: the entry's own bits `[4w, 4w+4)`. A leaf that separates early inside
  a window needs no partial-suffix field; the fold finds it alone in its half.
- A window with no split is skipped; its bits ride in the parent cell's prefix.
- Every key ends on a window boundary (272 = 4×68, 528 = 4×132), so no leaf ends inside a window.

### Cells

- Leaf: `suffix = key bits [4(w+1), keyBits)`. `keyBits` is 272 when the key's first nibble is 0 (zones
  0x00, 0x01) and 528 when it is F (0xFF); reserved zones are rejected. Value in the `eip8297` compact
  codec. Leaves of an account-stem row at window 67 carry no suffix.
- Branch: `prefix = bits [4(w+1), D)` exactly, `D` = the child subtree's top split; `L||R` = hashes of
  the two sides of the child's top split node. Child row key: `AppendBitPath` of
  `rowPath || slot || prefix` truncated to `floor(D/4)` nibbles.

### Keys and record value

- row key: `eip8297.AppendBitPath(rowPath)` (packed bits || byte(bitLen%8)), `bitLen%4 == 0`
- global root: `{0x08}`, outside the `AppendBitPath` key space (whose last byte is ≤ 7); the window-0 row
  exists only as the global rowRoot there
- bucket root: `AppendBitPath(0xFF || H(addr32))`, 264 bits; a bucket's rowRoot is its window-66 row
- state blob: under `KeyCommitmentState` in the bin domain, pbin framing (marker 0xB1) with a new format
  byte 0x20 in place of 0x10; the framing and its validator live in `execution/commitment/pbin_state_format.go`
  (`PBinValidateRowStateFormat`), so the datadir guard and the engine share them and they survive Task 16

```
hdr        u8   format | rootForm(row/ext/leaf) | hasExt
[selfExt]  u16 bitLen || packed bits                        ext-root only
childMask  u16; leafMask u16 (subset of childMask)
[extMask]  u16 (subset of childMask &^ leafMask)            branch cells with a non-empty prefix
branch     64 B L||R per branch cell, ascending slot
ext        per extMask bit, ascending: u16 bitLen || packed bits
leaves     per leafMask bit, ascending: packed suffix || vlen u8 || compact value
```

- Shapes: a row (ordinary, global rowRoot, bucket rowRoot) is
  `hdr || childMask || leafMask || [extMask] || branch || ext || leaves`; an extRoot is
  `hdr || selfExt || L || R`; a leafRoot is `hdr || packed suffix || vlen u8 || compact value`, the suffix
  running from the root's first bit (0 global, 264 bucket).
- hdr bits as v3's record header: bits 0-3 format (`recordFormat` = 0), bit 4 ext root, bit 5 hasExt
  (extMask present), bit 6 reserved, bit 7 leaf root; a row sets neither bit 4 nor bit 7. u16 fields are
  big-endian; slot `s` (the window's 4 bits, first bit most significant) is mask bit `1<<s`; packed bits
  run most significant first with zero padding, as `AppendBitPath` packs them.
- Tombstone: zero-length value. Ext and leaf roots appear only at `{0x08}` and bucket root keys, as v3
  allows its self-extension and leaf root only at depth 0.
- Decode is total and canonical: format equals `recordFormat`; bit 6 zero; bits 4 and 7 not both set;
  ext and leaf roots only at root keys; bit 5 only on rows, set iff extMask is non-zero; mask subsets;
  ≥2 cells in every row; ext bitLen ≥ 1; selfExt bitLen ≥ 4; an ext or selfExt ends at a split below the
  key's length (272 or 528 bits, from the zone); pad bits of every packed selfExt, ext and
  suffix zero; exact length; compact values canonical. Cross-row rules (prefix ends at the child's top
  split, L||R equals the child's fold, bucket record equals its upper cell) belong to the invariant
  walker.

### Root forms (global root and bucket roots)

- leafRoot: exactly one entry; packed key suffix from the root's first bit (0 global, 264 bucket) +
  compact value; the global root hash is its leaf hash
- rowRoot: top split in the root's first window (`[0,4)` global, `[264,268)` bucket); ordinary row layout
- extRoot: top split `D ≥ 4` (global) or `D ≥ 268` (bucket); `selfExt = bits [0, D)` or `[264, D)` +
  L||R; the top row lives at its own key; the global root hash is `H(0x01 || enc(selfExt) || L || R)`
- empty: no record; the global empty root is 32 zero bytes

### Fold

- leaf hash `H(0x00 || rowPath || slot || suffix || value32)`; a leaf's hash never depends on its
  position. Records store no leaf hash, as v3's records do not, so an untouched leaf is re-hashed from
  suffix + value on every fold of its row; v3's in-memory `LeafRefs` cache has no `pbt` counterpart.
- inside a row, recursion over occupied slots (`foldRange`): a node's prefix is the slot bits strictly
  between its parent's split and its own; ≤15 internal hashes per row
- branch cell hash `H(0x01 || enc([slot bits after its in-row parent split] || stored prefix) || L || R)`
- a row hands its top node's `(D, L, R)` to its parent, which hashes it with its own view of the prefix

### Mutation

- insert into an empty slot → leaf cell
- insert at a slot holding a different leaf → new row at window `floor(d/4)`, `d` = first differing bit;
  both leaves at their true slots; the cell becomes a branch with prefix `[4(w+1), d)`
- key diverging at bit `d` inside a branch cell's prefix, child top split `D`: if
  `floor(d/4) == floor(D/4)` the leaf joins the child row and the cell's prefix shortens to
  `[4(w+1), d)`; otherwise a new row at window `floor(d/4)` holds the leaf and the old child (prefix
  `[4(floor(d/4)+1), D)`, same L||R)
- an op list is sorted by key with at most one op per key; a drop precedes the writes under its prefix;
  `Process` rejects any other list
- a 32-byte zero value is a delete (eip:"Zero values and deletion"), checked on the 32-byte value before
  compact encoding
- collapses are evaluated once per row after all of the batch's ops, deepest row first, so a delete and
  an insert in the same row never collapse and re-split it: a row left with ≥2 cells stays and its parent
  cell's prefix ends at the row's new top split; a row left with one cell X collapses into the parent
  cell — a leaf X moves up with its suffix recomputed; a branch X moves up with its L||R and prefix
  `parent cell prefix || X's slot bits from the collapsed row's old top split || X's prefix`
  (eip:"Insertion and deletion"); a row left with no cells is tombstoned and its parent cell removed, and
  the parent row is evaluated in turn, since it can be left with one cell or none
- drop(264-bit prefix) → remove the covering cell and tombstone every row under it, read to enumerate
- global and bucket root forms follow the same rules with `selfExt` as the parent prefix
- merge ops resolved at the header stem, which the descent reads anyway: BASIC_DATA's `code_size` and
  CODE_HASH on stem creation (both depend on whether BASIC_DATA existed before the batch)

### Deltas

- one owner per key: a bucket task owns its bucket root record and its rows at window ≥ 66 (whale
  sub-tasks own disjoint subtrees; the bucket's top rows belong to the bucket join); a phase-B chain owns
  its upper rows; the final join owns the rows above the chains and `{0x08}`
- each owner emits one delta per key from the round-start prev to the final data; a drop's tombstone for
  a key the same owner rewrites is cancelled; equal data emits nothing
- reason: a naive collector that drops `Prev == Data` and applies in order without coalescing (as v3's
  `deltaParts.add` and `applyDeltas` do) keeps a wipe's tombstone when the rewrite is identical and
  deletes a live record
- the engine writes through its `PatriciaContext.PutBranch`; in the shadow role that context is the
  existing `BufferedPatriciaContext`, replayed only when both arms succeed

### Phases

- every storage-zone row at window ≥ 66 belongs to exactly one bucket (264 = 4×66); rows above belong to
  the upper tree
- phase A, storage buckets `0xFF || H(addr)`: one task per contract with dirty overflow slots
  (slot ≥ 64) or a wipe, longest first; starts with one Get of the bucket root record; whale buckets split
  inside their own rows. Result: an immutable bucket descriptor — empty; leaf (full key, value); or branch
  (`selfExt = bits [264, D)`, L||R). The path is part of the result because a deletion can expose an
  untouched survivor whose prefix is in no dirty key. The bucket root record and the upper
  cell are both built from the descriptor.
- phase B: header stems (BASIC_DATA, CODE_HASH/DELEGATION, header slots 0..63), code groups and the upper
  rows of all zones, in chains per zone and leading stem-hash nibble. Account-zone and code-zone chains
  never wait on phase A (BASIC_DATA carries no storage root); storage-zone chains wait for the buckets
  below them.
- one worker loop across both phases, written in `pbt` (errgroup + atomic task index, as v3's storage
  phase)

### Feed

`commitment.PBinFeed`, per changed account: plain address; final existence; final nonce, balance,
codeHash; `wiped`; `codeWritten` (a touched code key, independent of length, so an empty-code write
survives) with the final code bytes; changed slots (plain key, final value).

One adapter builds it: `BinFeedFromState(keys, codeKeys, wiped, reader)`, where `codeKeys` holds the
accounts with a code write. A plain-key set cannot supply it: accounts and code share the address key, and
`Updates.TouchPlainKey` in `ModeDirect` keeps only the deduplicated address. Values come from the reader;
code is hydrated only for `codeKeys` and must hash to the final codeHash, because CodeDomain keeps old
delegation bytes after a clear (`TestPBinTrieContextIgnoresClearedDelegationResidue`). Sources:

- `SharedDomainsCommitmentContext.ComputeCommitment` for the bin variant: its touched plain keys, and
  `codeKeys` recorded by `TouchKey` on `kv.CodeDomain` and reset with them — genesis, `eth_simulateV1`,
  history replay, rebuild. `wiped` stays empty: `DomainDelPrefix` is a per-key delete loop, so a wipe
  arrives as touched slot deletes (pinned by a test).
- the dual calculator on calcState: calcState's dirty plain keys; `codeKeys` = the accounts calcState saw
  a code write for; `wiped` = accounts calcState saw deleted or recreated inside the batch; reader =
  `asOfStateReader`.
- the BAL path: the BAL state's keys, `codeKeys` from the BAL's code changes, code from the BAL code
  reader; `wiped` stays empty: a BAL carries no create marker, so CREATE over storage is a known gap of
  the BAL path in both arms (`docs/backlog/commitment-bal-create-over-storage-wipe.md` in the main
  checkout); on every other block its roots equal the non-BAL path's.

### Translation (feed → tree ops sorted by key)

- `wiped` → drop `0x00 || H(addr)` and `0xFF || H(addr)` before any write under them
- final absent → drops only; code written earlier in the batch emits nothing (create-and-destroy
  inserts no chunk)
- BASIC_DATA from nonce and balance. `code_size` = len(final code) when `codeWritten`; else kept from the
  existing BASIC_DATA leaf when one exists and was not dropped in this batch (merge op); else 0 when the
  final codeHash is empty; else an error. Missing BASIC_DATA never means "no code".
- `codeWritten`: a delegation designator (`0xef0100 || addr`) → DELEGATION set, CODE_HASH deleted;
  otherwise CODE_HASH set, DELEGATION deleted, and chunks emitted (content-addressed, deduped per batch,
  never deleted — binary-trie behaviour, bounded by EIP-6780)
- a stem created without a code write → CODE_HASH = the final codeHash, empty (merge op)
- slot `s < 64` → header sub-index `64+s`; otherwise the storage zone
- every generated 32-byte zero value → delete, including BASIC_DATA and code chunks (code `0x00` chunks
  to 32 zero bytes); a zero-length compact CODE_HASH is keccak(""), not absence

### Integration

- dual: one calcState flush → v3-hex's `Feed` and the bin adapter's key set; both arms run concurrently;
  roles from `canonicalCommitmentDomain(blockTime)`; the shadow arm's writes go through
  `BufferedPatriciaContext` and replay only when both succeed; a shadow fold or replay error stops that
  domain via the existing stop marker; the step-boundary compute runs both and resets block flags once,
  after both; v3-hex defers its writes as v3-commitment does in the canonical role and writes through the
  buffer in the shadow role
- modes: hex-only unchanged; hex+bin requires v3-hex (`reconcileTrieVariant` refuses HPH and parallel
  HPH); bin-only = v3-bin on `kv.CommitmentDomain` and refuses `--experimental.commitment-v3`, whose
  schema switch (`EnableCommitmentV3Records`) would apply to the domain holding bin rows
- unchanged, keyed by domain: `CommitmentBinDomain` schema, shadow roots, stop marker, freeze,
  `restoreCommitmentLifecycle`, diffsets, prune/reset, retire cutoffs, E3 file walks; every read of a
  domain's state blob uses its variant's key (`KeyCommitmentV3State` for v3-hex): the freeze command,
  `readCommitmentBlockFromDB` in `stage_snapshots.go`
- BranchCache stays off for bin and commitment key referencing stays off, through the kept variant gates
- format guard: after `openFolder`, for bin-only and hex+bin datadirs, read the bin domain's
  `KeyCommitmentState` (DB or files) and run `PBinValidateRowStateFormat`; an old-format datadir
  fails `OpenFolder` with "rebuild the bin commitment domain", before any fold. A staged rebuild output
  is opened against the source's chaindata (`newTemporalDB` already skips the files-vs-DB gap check for
  it), so there the guard checks only the output's commitment files; execution startup stays strict.
  The guard sees the latest checkpoint only: an older file can still hold a format-0x10 record, which
  fails the row decoder's format check when first read (every old record's first byte sets the leaf or
  branch bit, so its format nibble is non-zero) with the same "rebuild" error, never a wrong root.
- rebuild: the translated ops go through an ETL collector sorted by tree key, and batches (capped by ops
  and bytes, partial accounts allowed) are cut from that global order, so consecutive batches cover
  increasing key ranges and never re-fold a finished subtree; a plain-key slice instead re-hashes the
  inherited structure it touches (the format-0x10 mainnet conversion's cost is under Post-Completion)
- RPC: `debug_executionWitness` on a bin block → `ErrBinCommitmentUnsupported`; `eth_getProof` and
  `eth_getWitness` already refuse bin blocks; `debug_shadowStateRoot` and `debug_migrationProgress`
  unchanged
