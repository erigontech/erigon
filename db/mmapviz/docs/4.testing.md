# mmapviz testing plan

Companion to `3.design.md`. Covers what gets automated (unit / syscall-level / integration /
privileged), what stays manual, the scenario matrix, the edge cases most likely to bite, and how
we validate the UI and Grafana stories. Layered like the code: the classifier/aggregator/scheduler are
pure functions (TDD from day one), the syscall layer is thin and verified against the real
kernel, the tiers above are integration surface.

Repo policy notes that shape this plan: TDD is the default for all new behavior (CLAUDE.md), and
tests may never be muted with `t.Skip` outside the canonical `testing.Short()` guard — so
privilege-dependent tests are **partitioned by build tag** (they don't exist in the default
suite), never skipped at runtime, and long-running soaks live outside `go test` entirely.

## 1. Unit tests (default suite, no privileges, deterministic)

**Classification** — the highest-value target, since every metric hangs off it:

- Table-driven: filename/relpath → `{sub, name, ext, tier}` for every real shape: state
  (`v1.0-accounts.0-1024.kv` + all of `AllV3Extensions`), blocks (`v1.0-000000-000500-headers.seg`,
  `.idx`), caplin, heimdall, every dbcfg mdbx dir, `nodes/eth68/mdbx.dat`, `caplin/indexing/mdbx.dat`,
  salt/`.torrent`/`.toml`/part files → `other`, tmp dir → `temp`.
- **Lockstep property test**: generate names *programmatically from the real builders*
  (`snaptype.SegmentFileName`/`IdxFileName`, the E3 schema renderers) across all registered types
  and versions, and assert classification never lands in `other`. This is the guarantee that a
  future layout change breaks a test in this package instead of silently degrading labels.
- Junk-resistance / cardinality: arbitrary garbage filenames (fuzz corpus) must map into the
  bounded label set (worst case `ext`-only or `other`) — a hostile or buggy filename must not be
  able to mint unbounded label values.
- `tier` derivation from range width, including boundary widths.

**Enumeration**:

- Dedupe by `(dev, inode)`: hardlink the same file twice in a temp tree → counted once.
- Symlinked snapshot dirs (operators do this): followed; symlink cycles: visited-set by
  `(dev, ino)` terminates the walk.
- Unreadable stray files (e.g. root-owned): skipped, counted in a `files_skipped` self-telemetry
  counter, never fatal. Vanishing entries between `readdir` and `stat`: same.
- Zero-byte files, sub-page files, and a sparse file (st_size ≫ blocks): sizes summed by
  `st_size`, no division blowups.

**Sweep mechanics** (syscalls injected via a small interface):

- Chunking: sizes that aren't 1 GiB multiples, final short chunk, size 0.
- Size changes mid-sweep (mdbx grows, files truncate): clamp to the fstat snapshot, no error.
- Error dispatch: `ENOSYS` → mincore fallback path selected once and logged once; `EOPNOTSUPP`
  (hugetlbfs) → file skipped + counted; `EINTR` → retried.
- Budget/rotation with a fake clock: N files, synthetic per-file durations → full pass completes
  within the target period; when the measured pass exceeds the CPU budget, the interval
  stretches (and un-stretches when load drops). Pure scheduler logic, fully deterministic.

**Aggregation & outputs**:

- Fake sweep results → exact gauge values per `{datadir, sub, name, ext, tier}`; two datadirs
  don't cross-contaminate; datadir label normalization (trailing slash, relative path).
- Heatmap bucketing: bitmap → K buckets on exact boundaries; file smaller than K; huge-file
  downsampling.
- `/debug/pagecache` JSON: golden-file schema, resident-desc ordering, glob filter; heatmap
  endpoint rate-limiter (hammering it cannot exceed the sweep budget).
- inode→path resolver (for `--trace.io`): unknown inode → `other`; deleted-but-open file retains
  last-known name; re-walk on miss.

**History store** (`3.design.md` §6.4; pure logic first, MDBX behind a small interface):

- Strip codec property test: 4-bit quantize + RLE encode/decode roundtrips, including worst
  cases (alternating buckets, all-zero, all-max, single-bucket files).
- Write-on-change: identical consecutive strips produce no new row; a one-bucket change does.
- Identity & lineage (FR11): inode reuse mints a new `file_id`; a simulated merge (two files
  replaced by one covering their union) yields correct lineage by range containment, and the
  step-line projection paints the right file's values on each side of the seam.
- Retention with a fake clock: oldest-first pruning honors `--store.max-size` and the retention
  window; downsampling boundaries exact.
- Rollup consistency: `rollups` rows equal a recomputation from `sweeps` for the same tick — the
  same values must feed Prometheus and the UI.
- Monotonic sweep sequencing under wall-clock jumps (backwards `ts` recorded, order preserved).
- Fill classification (FR7/FR11): synthetic sweep sequences → warmup/refault/steady labels; a
  region evicted then re-filled must classify as refault, first-ever touch as warmup; evictions
  on a file that disappears in the same/adjacent sweep classify as **deleted** (excluded from
  thrash); fills on a merge-minted file inside its lineage window classify as **merge warmup**.
- Block↔time lookup (FR6): annotation streams containing an unwind (block numbers going
  backwards) → block→time returns *all* matching intervals; time→block returns the sample at or
  before T.
- Job-event derivation (FR6/FR11): from walk history — new file whose range = union of
  disappeared files → merge event with correct inputs/output; new tip-step file with no file
  parents → collation event; `.tmp`/partial build files emit nothing until the rename.
- Host/neighbor context (FR6f): golden parses of `/proc/meminfo`, PSI, and `/proc/vmstat`
  delta computation (counter reset/wrap safe); cgroup `memory.current`/`memory.pressure`
  sampling; an unreadable or absent cgroup (permissions, v1 host) degrades to host-only with a
  single log line.
- Unwind-episode derivation (FR6): synthetic position sequences → episodes with correct depth
  and bounds: backstep + fast catch-up to a head **below** the old high-water mark (shorter
  fork) closes at the plateau, not at the old mark; catch-up ending exactly at tip cadence
  closes the episode; a second backstep during catch-up deepens the open episode (one episode,
  max depth); the whole episode inside a single poll interval → single-sample dip still yields
  an episode; stream ending mid-episode → left open; a backstep adjacent to an endpoint gap
  (restart) opens nothing.

## 2. Syscall-truth tests (default suite, Linux, unprivileged — real kernel, tolerant asserts)

These run the real `cachestat`/`mincore` against temp files; CI (ubuntu 24.04, kernel 6.8) has
both. Assertions are *directional*, not exact, because the page cache is shared machine state:

- Write a small file → `nr_cache` ≈ its pages, `nr_dirty > 0` before fsync.
- fsync + `posix_fadvise(DONTNEED)` → `nr_cache` drops to ~0.
- Read half the file → resident fraction ≈ half (± fault-around/readahead slack).
- cachestat totals ≈ mincore totals on the same file (internal cross-check, replaces a vmtouch
  dependency).
- **Observer-effect invariant**: sweeping a cold file twice leaves it cold — enumeration, open,
  fstat, cachestat, mincore must fault nothing in. This pins the "measurement doesn't perturb"
  property the whole design leans on.
- tmpfs file: resident == size, eviction fields meaningless-but-harmless (no NaN/div-by-zero).

Flake budget: these tolerances (e.g. "≥ 90% resident", "≤ 10% + readahead window") should survive
a loaded CI box; if one flakes, tighten the *setup* (smaller files, fsync barriers), never the
policy (no skips).

## 3. Integration tests (default/`test-all` suite)

- **Golden fixture datadir**: a handcrafted tree with realistic names across every class
  (state/blocks/caplin/heimdall, all mdbx dirs incl. `nodes/eth68` and `caplin/indexing`, tmp,
  torrent debris) → run the one-shot path (library call, plus one subprocess run of
  `erigon mmapviz --json`) → golden classification, counts, and JSON output.
- **`--serve` end-to-end**: start the exporter on an ephemeral port against the fixture → scrape
  `/debug/metrics/prometheus`, parse with `expfmt`, assert families/labels/values; assert
  `mmapviz_sweep_seconds`/`sweep_age` present; `promtool check metrics`-style lint via
  client_golang's testutil.
- **Coexistence with a live node** (the load-bearing invariant): start a dev-chain erigon
  (existing integration-test harness), point mmapviz at its datadir, assert (a) mmapviz takes no
  datadir lock and never opens mdbx/snapshots as objects, (b) the node keeps committing blocks,
  (c) chaindata metrics are non-zero, (d) node shutdown/restart mid-sweep doesn't error the
  sidecar.
- **Churn-during-sweep**: a goroutine continuously creating/renaming/deleting fixture files
  (simulating merges) while the sampler loops — no errors, no stale-fd leaks (`/proc/self/fd`
  count stable), vanished files land in self-telemetry. A full simulated merge (sources deleted
  + a union file created) must additionally yield: tombstoned rows still queryable, step-line
  continuity across the seam, no thrash misclassification of the cleanup, and a recorded merge
  event with the right inputs → output; a simulated collation (new tip-step file, no parents)
  yields a collation event.
- **Multi-datadir**: two fixtures, one sidecar → series split correctly by `datadir`.
- **Store crash-safety**: `kill -9` the serving sidecar at random points while sweeping a
  churning fixture, repeatedly → reopen is clean (no partial rows visible) or auto-resets with a
  logged reason; never a crash loop.
- **Store lifecycle**: schema-version bump → wipe-and-restart path taken exactly once;
  `--store.max-size` enforced under sustained churn; disk-full (tiny tmpfs store dir) degrades
  to metrics-only with self-telemetry, sampling continues.
- **History API goldens**: seed a store with synthetic history → golden responses for
  `/api/v1/{files,sweeps,strips,rollups,consumers,annotations,streams}`, including scrubber
  (point-in-time), scrub-by-block, and two-point-diff queries.
- **LOD downsampling**: `from/to/step` bucketed responses preserve extremes (min/mean/max per
  bucket) — a single-sweep fill spike must survive a 14-day window; bucket boundaries exact;
  narrow windows return raw sweeps unmodified.
- **Incremental cursors**: a sequence of `since=` delta fetches reassembles to exactly the
  full-window response, including across store pruning happening mid-sequence.
- **Activity annotations**: a mocked node metrics endpoint drives the poller — normal advance,
  an unwind, endpoint down (annotation gap recorded, sweeps unaffected, no crash), endpoint
  returning garbage (ignored + self-telemetry), prune progress samples → prune spans with
  correct bounds, torrent upload/download rate samples → `torrent` stream recorded, devp2p
  egress samples → `devp2p` stream recorded, and a
  backstep + catch-up sequence → one unwind episode with correct depth (none when the backstep
  straddles an endpoint gap). Overlapping collation and prune spans
  (prune follows collation) must stay distinct — they come from different sources (walk vs
  metrics). The live dev-node coexistence
  test additionally asserts real annotations get recorded when `--node.metrics.url` is set.
- **Performance**: `go test -bench` benchmarks for sweep ns/resident-page and enumeration time at
  10k files — reported, not asserted (shared runners make hard time asserts flaky); the design's
  budget numbers (§9 of `3.design.md`) are re-validated manually per release instead.

## 4. Privileged tier (`--trace.io`) — build tag `ebpf`, separate CI job

Not in the default suite (needs root/CAP_BPF); compiled under `//go:build ebpf` and run by a
dedicated job/make target (`make test-mmapviz-ebpf`, `sudo` available on GitHub runners), so the
no-skip policy is never tripped.

- Attach → `dd` a known cold file → per-inode fill bytes ≈ bytes read (± readahead), attributed
  to the right file; unrelated system activity lands in `other`, not in our classes.
- Eviction counter: `posix_fadvise(DONTNEED)` on a warm file → evict bytes ≈ its size.
- Access-mechanism tagging: fault a cold file in via mmap and `pread` another → fills tagged
  fault-driven vs syscall-read-driven respectively; the per-task flag clears on syscall exit
  (no leakage into subsequent faults by the same task).
- Folio-order accounting: totals computed via `4096 << order` match `dd` byte counts on a
  filesystem doing large folios as well as on order-0 (loopback xfs vs ext4 if available).
- Lifecycle hygiene: detach on shutdown leaves no pinned programs/maps (`bpftool prog list` diff
  before/after); LRU map overflow (tiny map + many inodes) degrades by evicting cold entries and
  increments a `trace_map_evictions` self-counter rather than miscounting hot ones.
- Inode reuse: delete a tracked file, create a new one that reuses the inode (loopback fs makes
  this reproducible) → resolver re-stats on the next drain and does not attribute old bytes to
  the new name (documented limitation: at worst one drain interval of misattribution).
- Kernel-matrix option: run this suite inside qemu microVMs (cilium/ebpf's `vimto`-style harness)
  against 6.5 (cachestat floor), 6.8 (fleet), latest stable — nightly, not per-PR.

## 5. Manual test matrix

| Scenario | What to do | Pass criteria |
|---|---|---|
| Real archive node | run `--serve` against a ≥ 2 TiB datadir for 24 h | sweep CPU within budget (`mmapviz_sweep_seconds`), totals cross-check vmtouch/pgcacher ±5%, node exec/RPC latency metrics unchanged vs the prior day |
| Memory pressure | `stress-ng --vm` (or a second syncing node) on the same host | `recently_evicted` climbs on the squeezed classes, fills rise correspondingly; numbers return to baseline after |
| Cold restart / warmup | restart node; optionally `drop_caches` first (test box only) | resident collapses → refill curve visible per class; fills spike then decay; heatmaps of hot `.kv` re-densify |
| `--trace.io` cross-check | busy node, compare fill bytes/s vs `iostat` device reads and `process_io` panel | strong correlation; per-class sum ≤ device total |
| Old kernel | any 5.x box | one clear degradation log line, mincore fallback or clean disable; no crash loop |
| Containers | compose deployment with datadir volume | metrics correct despite different mount path; `--trace.io` refuses politely without privileges |
| Week-long soak | leave `--serve` + `--trace.io` running across merges, node restarts, downloader activity | flat sidecar RSS, flat fd count, no BPF map growth, no gaps in Prometheus |
| Retention soak | 14 d `--serve` with the history store on an archive node | store within `--store.max-size`, pruning observable, UI scrubber/diff/heat views responsive at full retention |
| Non-Linux build | build/run on macOS/Windows | command exists, prints "unsupported platform", exit code ≠ 0 |

## 6. Grafana & UI validation

The UI has real logic now (time-window store, LOD cache, RLE decoder, URL-hash codec, follow
mode) and must be tested without violating the no-npm invariant — so **no jest/vitest**. The
strategy keeps Go as the single test runner and drives a real browser via **chromedp** (a Go
package; the only extra CI dependency is headless Chrome, standard on runners):

- **JS pure-logic tests**: the UI's algorithmic modules (RLE decode, window/LOD-cache math,
  URL-hash codec, episode/label formatting) are plain ES modules with no DOM dependencies. A
  `go test` boots the sidecar against a seeded store, chromedp loads a test page that imports
  those modules and runs an assertion table, and results report back to the Go test. The
  keystone is **cross-language goldens**: Go encodes a strip (its own tested codec), JS decodes
  it in the browser, values must match exactly — the wire format can never drift between the
  two implementations.
- **e2e behaviour via chromedp against a deterministic seeded store**: load `/ui`; assert
  follow-mode renders; switch tabs; dispatch real wheel/drag events and assert the shared
  time-window store moved (the app exposes a `window.__mmapviz` state hook for tests); scrub by
  block number → correct interval; scrub to a pre-merge time → since-deleted files render; deep
  link with a URL hash → identical state. Canvas correctness: state-hook asserts are primary;
  a small set of canvas-hash goldens (fixed data, fixed viewport, fixed DPR) cover the heat
  views — regenerated deliberately on visual change, never fuzzily "fixed".
- **Smoke floor** (kept from before): `/ui` serves its embedded assets; every view's data
  endpoint returns non-empty for the fixture store.
- **Manual visual sign-off** stays: the §5 pressure-demo scenario against the acceptance bar in
  `2.visualisations.md` §7 (newcomer answers class→file→region→when, one action per question).
  Full screenshot-diff automation remains deferred until the UI stabilizes; the canvas-hash
  goldens above are the narrow, deliberate version of it.

Grafana automated smoke (nightly or on dashboard change):

1. `docker compose up` prometheus + grafana + a dev node + mmapviz (fixture or dev datadir).
2. Assert the `mmapviz` target is `up` via the Prometheus API.
3. Walk `pagecache.json`, extract every panel expression, run each against the Prometheus API:
   no parse errors, and the panels expected to be live on a fresh node return non-empty series.
4. Lint: valid JSON, pinned datasource UID convention, `grafana/dashboard-linter` if available.
5. **Window-vs-cadence check**: fail if any range window used with sampler-fed gauges (`delta`,
   `*_over_time`) is shorter than 2× the default sweep interval — the classic way these panels
   silently render garbage (see §7).

Manual visual checklist (once per dashboard change, on the pressure-demo scenario from §5 so the
panels have something to show): byte units are IEC everywhere; stacked composition sums track the
host `Cached` context line; legend templates render class names not label soup; the `datadir`
template variable filters every panel; thrash panel visibly reacts during the pressure test;
steppy gauges look intentional (sweep cadence documented on the dashboard) rather than broken.

## 7. Nasty edge cases — the lookout list

| Edge case | Failure it causes | Covered in |
|---|---|---|
| Sampler cadence ≫ scrape interval | gauges look frozen; `delta()` windows shorter than 2 sweeps render zeros/noise | §6 window check; dashboard doc note |
| File vanishes between readdir/stat/open (merges) | spurious errors or sweep abort | §1 enumeration, §3 churn test |
| Inode reuse after merge delete | eBPF counters attribute old IO to new file | §4 inode-reuse test; accepted ≤ 1 drain interval |
| Sparse mdbx.dat / geometry vs allocation | resident% denominators mislead | §1 sparse test; doc note (st_size chosen) |
| Symlink cycles / symlinked snapshot dir | infinite walk or missed files | §1 |
| Hugetlbfs / exotic fs (`EOPNOTSUPP`) | sweep abort | §1 dispatch |
| tmpfs dev datadirs | meaningless eviction signals read as thrash | §2; doc note |
| Junk filenames | label-cardinality explosion | §1 fuzz |
| BPF LRU map overflow on busy hosts | silent undercount of hot files | §4 overflow test + self-counter |
| Overlayfs/bind mounts in containers | tracepoint `s_dev` ≠ stat dev → resolver misses | §5 container run; resolver keys tested both ways |
| Non-4KiB page size (arm64 16K) | wrong byte math everywhere | `unix.Getpagesize()` throughout; unit-test parametrized |
| Sidecar restart | counter resets | Prometheus-native (`rate` handles it); noted in dashboard |
| Two sweeps racing (serve + one-shot) | none expected — read-only | §3 coexistence covers implicitly |
| Observer effect (sweep faults pages in) | sidecar inflates the very metric it measures | §2 invariant test |
| Store on full disk / IO errors | crash loop or lost sampling | §3 lifecycle test (degrade to metrics-only) |
| Store inside a monitored datadir | sidecar measures its own store as node cache | walker exclusion unit test; `sub="mmapviz"` labeling |
| Wall-clock jump (NTP step) | history ordering breaks, scrubber lies | §1 monotonic-sequencing test |
| Unwind / reorg | block↔time assumed monotonic → wrong scrub-by-block answers | §1 lookup test (interval semantics) |
| Merge cleanup read as thrash | deletion-invalidated pages fire the same eviction tracepoint as reclaim → false thrash alarms | §1 classification test; §3 churn assert |
| Partial/tmp build files | premature merge/collation events; build output misclassified as a data file | §1 job-event derivation test (nothing before rename) |
| Prune vs collation confusion (prune follows collation) | prune's `mdbx.dat` dirty burst labeled as collation scan | distinct sources + overlapping-spans case in §3 activity-annotations test |
| No `--node.metrics.url` | prune spans and unwind episodes absent; `mdbx.dat` writeback bursts unlabeled | documented asymmetry (`3.design.md` §6.4); UI must render unlabeled bursts honestly |
| Restart transient read as unwind | node gauges briefly read low after restart → phantom deep-unwind episode | §1 derivation gap-guard; §3 annotations test |
| Embedded downloader shares the node's tgid | seeding fills unattributable by consumer role | access-mechanism tag (mmap fault vs `pread`) attributes it per file (`3.design.md` §6.3/§6.4(f)); §4 tagging test |
| Hash-verification/recheck bursts | whole-file syscall reads misread as seeding | shape (whole-file sequential) + downloader-state corroboration; documented in the §6.4(f) ladder |
| devp2p serving vs historical RPC | same class signature (blocks/receipt fills) conflated inside the node | egress-stream correlation + offset-scatter shape; standalone rpcdaemon separates by role; in-node split deferred to Phase 4 (`3.design.md` §6.4(g)) |
| Peer-driven regeneration (receipts/BAL not persisted) | serving re-executes blocks → fills on state/history classes mimic execution | frozen-history/II range signature (tip exec rarely touches) + egress correlation; regen never moves the chain stream (no fake unwinds); Phase 4 `receipts-regen`/`bal-regen` sources |
| Unwind shorter than the annotation poll | episode missed entirely | documented (NFR7); annotations poll decoupled and faster than sweeps; node unwind counter preferred where exposed |
| Node metrics endpoint down/garbage | annotation poller wedges the sweep loop | §3 chain-annotations test (gap + telemetry, sweeps independent) |
| Schema bump on upgrade | silent misreads of old rows | §3 wipe-and-restart test |

## 8. CI wiring

- §1 + §2 → normal `go test` (they're fast; part of `make test-short`).
- §3 → `make test-all` tier (dev-node coexistence reuses the existing integration harness).
- §4 → separate opt-in job (`ebpf` build tag + sudo runner), plus nightly kernel-matrix variant.
- Store unit/codec/identity tests → normal `go test`; store crash-safety + API goldens →
  `make test-all` tier.
- §6 UI tests (chromedp) + §9 golden journey (unprivileged variant) → `make test-all` tier
  (needs headless Chrome); golden journey privileged variant → the §4 ebpf job.
- §6 Grafana smoke → nightly and on any change under `cmd/prometheus/dashboards/` or
  `db/mmapviz/`.
- Manual matrix (§5) → release checklist for the mmapviz component; the archive-node soak and
  `--trace.io` cross-check gate the "flip default on" decision in `3.design.md` §11.

## 9. The golden journey — one whole-system e2e

Everything above tests a layer; this one deterministic scenario exercises the entire pipeline —
collection → classification → store → annotations → API → UI — in a few minutes, and is the
single test that answers "does mmapviz work":

1. **Arrange**: temp fixture datadir (realistic names across every class, small files); a mock
   node-metrics endpoint replaying a script: blocks advance, one unwind (backstep + catch-up),
   prune progress samples, torrent upload-rate and devp2p egress samples.
2. **Act** (while the sidecar runs `--serve` with a seconds-scale interval): warm some files by
   reading them; fsync + `fadvise(DONTNEED)` others (evictions); execute a scripted merge
   (delete two files, create their union) and a scripted collation (new tip-step file); `kill
   -9` the sidecar once mid-run and restart it.
3. **Assert**, at every boundary:
   - Prometheus rollups: expected classes present, resident/evicted bytes directionally right.
   - API: the merge event (correct inputs → output), the collation event, the unwind episode
     (correct depth), block labels; the host stream present and the mocked torrent/devp2p
     streams recorded; tombstoned files queryable at pre-merge timestamps; history seamless
     across the kill.
   - Classification: first-touch fills = warmup; merge cleanup = deleted, not thrash.
   - UI (chromedp): follow mode shows the run; scrub to pre-merge time renders the old layout;
     scrub-by-block lands on the unwind; the episode and job spans are drawn (state-hook
     asserts).
4. **Variants**: unprivileged (cachestat signals only) in `test-all`; privileged (`--trace.io`,
   byte-exact fill assertions) in the ebpf job.

If a future change keeps every §1–§7 test green but breaks the golden journey, the journey wins
— it is the executable form of `1.requirements.md` §2.
